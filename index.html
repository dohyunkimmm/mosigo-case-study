03 / CUSTOMER & VALUE

누가 결정하고 누가 이용하는가

고객의 역할이 다른 점을 제품과 정책에 반영했습니다.

우선 고객 가설

자녀 · 예약자

평일 동행이 어렵거나 부모와 떨어져 거주합니다. 매니저 선택과 진행 확인에 가치를 느낄 수 있습니다.

이용자

부모 · 동행 대상자

서비스 수용, 개인정보 동의, 이동 안전과 현장 경험이 중요합니다.

공급·운영

매니저 · 운영자

배정 가능 시간, 취소·예외, 계정·공유 권한과 원가를 관리합니다.

핵심 Job Story 고객 가설

“부모의 병원 방문에 함께하기 어려울 때, 신뢰할 수 있는 매니저를 선택하고 진행 상황을 확인하고 싶다.”

기능적 가치

비교 → 대리 예약 → 동행 상태 → 재예약을 연결합니다.

신뢰 조건

대상자 동의, 정보 최소 수집, 공유 권한, 사고 대응이 전제입니다.

04 / STRATEGY & TRADE-OFFS

왜 자녀 중심의 대리 예약인가

같은 병원동행 문제라도 예약 주체와 운영 방식에 따라 제품의 구조가 달라집니다. 세 가지 경험 설계 대안을 비교한 후속 전략 검토입니다.

OPTION A · SELF SERVICE

부모 직접 신청

이용자가 직접 병원과 매니저를 찾고 예약합니다.

장점
예약자·이용자 관계가 단순함
고려할 점
자녀의 원격 지원·진행 확인 과업을 별도로 해결해야 함
OPTION B · ASSISTED

상담 지원 중심

상담 또는 운영 인력이 대리 신청과 변경을 돕습니다.

장점
복잡한 예외 상황에 대응하기 쉬움
고려할 점
운영 인력·응대 비용에 따른 확장성 검토 필요
SELECTED HYPOTHESIS · FAMILY FIRST

자녀 직접 예약

자녀가 비교·예약·진행 확인을 한 흐름에서 관리합니다.

기대 가치
대리 예약과 보호자 정보 요구를 동시에 연결
설계 조건
부모 동의, 예약 소유권, 공유 권한의 분리
선택한 전략 방향 · 후속 분석

우선 고객은 ‘부모의 진료를 준비하는 자녀’로 가정합니다. 서비스 전체에서 매니저 비교 → 대상자 동의 → 예약 → 진행 확인이 이어지도록 설계하되, 실제 고객 선호와 운영 비용으로 타당성을 검증합니다.

가치와 복잡성의 교환

자녀의 정보 확인 부담을 낮추는 대신, 대상자 동의와 제3자 접근 권한을 명확히 설계해야 합니다.

제품과 운영의 경계

예약·공유 흐름은 프로토타입으로 보여주고, 현장 매니저 배정·실제 병원 예약은 별도 운영 타당성 검토로 둡니다.

G0 / 고객인터뷰 메모, 문제·대안 선택 이유, 과업 관찰 기록대리 예약의 필요성과 우선 고객이 확인되는가
G1 / 운영공급 가능 시간, 실제 원가, 동의·취소·책임 정책제한 지역에서 안전하게 운영할 조건을 갖췄는가
G2 / 제품예약·공유·복구 QA, 사용자 과업 결과, 수정 내역핵심 여정과 접근 권한이 검증 기준을 충족하는가
G3 / 사업재예약·지원 비용·실제 단위경제성 데이터확장 또는 모델 변경을 결정할 근거가 있는가

위 통과 기준은 수치 목표를 임의로 채우지 않은 의사결정 프레임입니다. 정량 기준은 기초 조사와 파일럿 운영으로 설정합니다.

QA·UAT 예시 실행 계획

과업통과 기준점검할 예외
부모 예약자녀가 도움 없이 요청 완료예약자·대상자 혼동, 재진입 시 상태 유실
매니저 비교가격·조건을 설명하고 적합한 선택 완료비교 정보 누락, 조건 불일치
상태·공유보호자가 현재 상태를 설명, 정책에 맞는 권한 확인만료 링크 접근, 권한 범위 오류, 상태 전환 누락

현재 단계는 퍼널 측정과 과업 테스트 설계입니다. 운영 지표·사용자 테스트 결과는 실제 검증 과정에서 기록하며 분석 이벤트에서 민감정보를 제외합니다.

09 / DECISION MEMO

단계적 사업화 검증

핵심 고객·공급 조건·수익성을 차례로 검증하고, 그 결과로 출시·제휴·확장 방식을 선택하는 전략을 제안합니다.

RECOMMENDATION

자녀 대리 예약형 병원동행의
사업화 조건을 검증합니다.

선택 가능한 방식

제한 지역 직접 제공 또는 기존 사업자 협업·중개. 수익 인식, 공급 원가, 책임 범위를 비교합니다.

결정 전 확보 자료

고객 인터뷰, 매니저 공급 단가, 실제 이용 흐름, 개인정보·안전 검토, 계약 조건.

G0~G2 검증 결과를 바탕으로 사업화·지역 확대 여부를 판단합니다.

실행 모델 선택 기준

OPTION 01 · DIRECT

제한 지역 직접 제공

서비스 품질 관리가 핵심인 경우 검토. 매니저 수급, 건당 원가, 사고 대응 역량 확인이 우선입니다.

OPTION 02 · PARTNER

기존 사업자 협업

공급 안정성이 핵심인 경우 검토. 수수료, 데이터·고객 책임, 예약 상태 연동 조건을 비교합니다.

OPTION 03 · EXPAND

기업·공공 제휴 확장

반복 수요와 운영 경제성이 확인되면 검토. 도입 주체별 구매·운영 절차가 추가로 필요합니다.

세 방식은 실제 계약 체결이나 출시 경험이 아닌 후속 전략 선택지입니다.

IT기획 · 전략기획 · PM 채용 요구 역량과의 연결

요구 역량이 사례에서 제시한 근거증빙 수준
시장·문제 정의경쟁 앱·리뷰 조사, 예약자·이용자 역할 분리팀 조사 기반 · 원문 재분류 계획
IA·PRD·정책사용자 여정, 기능·권한·예외와 인수 기준 정리, 원본 코드·테스트 연결프로토타입 증거 + 후속 기획안
BM·재무거래액·수수료 매출·공헌이익 모델과 민감도사업성 시나리오 · 실제 원가 검증 계획
