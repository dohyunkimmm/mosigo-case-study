01 / OVERVIEW & PROBLEM

서비스를 사용하는 사람과
예약을 결정하는 사람이 다르다면?

부모의 병원동행을 예약하는 자녀의 관점에서 문제를 다시 정의했습니다. 단일 예약 화면이 아니라 선택 전부터 동행 후까지 연결된 경험을 설계하는 과제입니다.

01 / DISCOVER

사용자 문제 정의

경쟁 앱과 리뷰를 조사해 지역별 접근성, 본인 신청 중심 흐름, 매니저 비교 정보 부족을 정리했습니다.

02 / DECIDE

자녀의 대리 예약에 집중

가족 등록·매니저 비교·진행 공유·재예약을 하나의 이용 흐름으로 연결했습니다.

03 / EXECUTE

예약부터 재이용까지 설계

가입부터 재예약까지 프로토타입을 구현하고 이후 예약 보존·공유 권한·운영자 화면을 추가했습니다.

04 / POSITIONING & DIFFERENTIATION

최초가 아닌,
선택과 확인의 경험에 집중

서비스 존재 자체보다 자녀가 예약을 결정하고 관리하는 과정에 집중합니다. 경쟁사보다 우수하다는 주장은 실제 대안 비교·사용자 검증 이후에만 가능합니다.

BEFORE

가족·지인의 직접 동행

ALTERNATIVE

민간·공공 병원동행

서비스별 지역, 가격, 자격, 매칭·운영 조건을 비교해야 합니다.

GATE 0

GATE 1

매니저 수급, 실제 원가·취소·안전·동의 책임 검토 → 제한된 지역에서 운영 가능한지 판단

GATE 2

MVP 흐름 검증

예약·매칭·공유·권한 제어 → 과업 완료·상태 정확성·비인가 접근 차단 확인

GATE 3

반복 이용·운영 검증

재예약, 고객지원, 취소/변경 기록 → 반복 사용 가치와 운영 부담 측정

GATE 4

지역·채널 확장 판단

단위경제성과 운영 안전성 확보 후 지역 확대, 기업복지·공공 위탁·AI 기능 적용 검토

진행 중단 기준

08 / FUNCTIONS, POLICIES & TRUST

매칭 기능뿐 아니라
책임과 접근 범위까지 설계했습니다.

헬스케어 연계 서비스는 UI 완성도만으로 신뢰를 보장할 수 없습니다. 정보 접근·공유·권한·사고와 같은 운영 정책을 기능과 구분해 관리해야 합니다.

프로토타입에 구현·반영

화면 설계에 반영

신뢰정보·안전지원

매니저 자격·신원 관련 정보, 예상 비용·민감정보 동의, 안심번호·신고·동행 타임라인

시연용 기능

AI·의료정보·결제

추천, AI 진료 요약, 건강정보 연동, 결제 및 정산은 실제 의료 서비스 운영·외부 시스템 연동 성과가 아닙니다.

필요한 추가 검토

법률·안전·권한 검증

제3자 제공·민감정보 처리·리포트 표현은 전문가 검토가 필요합니다. 정책 화면의 존재가 법적 적합성을 입증하지는 않습니다.
