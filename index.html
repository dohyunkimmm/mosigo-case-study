01 / PROJECT BRIEF

문제에서 사업 판단까지

MOSIGO는 부모의 병원동행을 자녀가 준비하는 상황을 중심으로 설계한 서비스 프로토타입입니다.

문제

예약자와 이용자 분리

부모는 서비스를 이용하고 자녀는 검색·선택·예약·확인을 담당합니다.

핵심 선택

자녀 중심 여정

가족 등록, 매니저 비교, 진행 확인, 재예약을 하나로 연결합니다.

판단

사업화 전 조건부 검증

수요·공급·원가·안전을 확인한 뒤 확대 여부를 결정합니다.

핵심 관찰

예약자 ≠ 이용자

자녀가 검색·비교·확인을 맡을 수 있다는 관점으로 요구사항을 다시 묶었습니다.

관찰 → 요구사항 → 검증

문제 가설제품 요구사항다음 확인
접근성지역·시간 조건의 공급 가능 여부 표시지역별 공급과 예약 실패 원인
대리 예약예약자·동행 대상자 구분, 동의·권한 관리부모·자녀 과업 테스트
신뢰·정보매니저 비교 기준, 요금·변경 조건, 진행 공유선택 이유·지불 의향·상태 이해
외부 벤치마크 · 동행돌봄인 · 고위드유 · 서울시 병원안심동행. 공개 자료 비교용이며 기존 팀 조사 7종과 같은 표본이라고 단정하지 않습니다.
03 / CUSTOMER & VALUE

누가 결정하고 누가 이용하는가

고객의 역할이 다른 점을 제품과 정책에 반영했습니다.

우선 고객 가설

자녀 · 예약자

평일 동행이 어렵거나 부모와 떨어져 거주합니다. 매니저 선택과 진행 확인에 가치를 느낄 수 있습니다.

이용자

부모 · 동행 대상자

서비스 수용, 개인정보 동의, 이동 안전과 현장 경험이 중요합니다.

공급·운영

매니저 · 운영자

배정 가능 시간, 취소·예외, 계정·공유 권한과 원가를 관리합니다.

핵심 Job Story 검증 전 가설

“직접 동행할 수 없을 때, 믿을 수 있는 사람을 선택하고 부모의 진행 상황을 확인하고 싶다.”

기능적 가치

비교 → 대리 예약 → 동행 상태 → 재예약을 연결합니다.

신뢰 조건

대상자 동의, 정보 최소 수집, 공유 권한, 사고 대응이 전제입니다.

구현 경계 · 원본은 실병원 예약·실결제·의료 판단을 제공하지 않습니다. 특히 공유 토큰의 예약 변경 권한은 운영 정책 결정이 남아 있어 “열람 전용”으로 단정하지 않습니다.

06 / PRIORITIZATION & DELIVERY

무엇부터 만들고 어디서 멈출 것인가

기능의 양보다 수요·공급·권한이 성립하는지 먼저 판단합니다. 단계와 순서는 후속 제안이며 실제 운영 일정이나 팀 공식 승인 이력은 아닙니다.

우선순위할 일결정 기준
P0 · 필수고객 문제 인터뷰, 공급·원가 확인, 예약 주체·공유 권한 정리수요 근거와 안전한 최소 운영 가능 여부
P1 · 검증핵심 예약 흐름 과업 테스트, 오류·취소·복구 QA, 실제 원가 기록과업 완료·오류 재현 및 운영 부담
P2 · 확장재예약, B2B/B2G 제휴, AI 기능의 범위 검토수익성·운영 안정성 입증 이후

실행 게이트

G0

문제 확인

자녀·부모 과업, 지불 의향, 대체재와 선택 이유를 확인합니다.

G1

공급·운영

매니저 수급, 원가, 취소·사고 책임, 민감정보 처리 검토.

G2

제한 검증

예약·공유·복구 예외를 테스트하고 관찰 결과로 다음 배포를 결정.

G3

확장 판단

재예약·지원 비용·공헌이익 검증 후 지역·제휴 확대 여부 결정.

QA 근거 구분 · 원본에는 자동 테스트·Chromium QA·읽기 전용 Production Smoke 기록이 있습니다. 실제 iPhone/Android 셀룰러 QA와 일부 운영 보안 조치는 미완료입니다. 실기기 QA 계획 ↗
07 / METRICS & VALIDATION

완료를 선언하기 전에 측정한다

실제 전환 성과는 아직 집계하지 않았습니다. 이벤트·분모·과업 성공 기준을 먼저 정의합니다.

퍼널

예약 완료율

예약 완료 세션 ÷ 예약 시작 세션

이벤트: start → manager_selected → submit_success. QA·중복 세션 제외 규칙 필요.

사용성

매니저 선택 성공률

조건에 맞는 선택을 완료한 참가자 ÷ 과업 참가자

선택 근거 설명 여부와 이탈 단계를 기록.

정보 이해

상태 이해도

현재·다음 단계를 정확히 설명한 참가자 ÷ 응답자

보호자 진행 화면 과업 기반 측정.

리텐션

90일 내 재예약률

90일 내 재예약 고객 ÷ 추적 가능한 완료 고객

관찰기간 90일은 제안 값으로, 실제 운영 기준이 아닙니다.

QA·UAT 예시 실행 계획

과업통과 기준실패·예외
부모 예약자녀가 도움 없이 요청 완료예약자·대상자 혼동, 재진입 시 상태 유실
매니저 비교가격·조건을 설명하고 적합한 선택 완료정보 부족, 조건 불일치
상태·공유보호자가 현재 상태를 설명, 정책에 맞는 권한 확인만료 링크 접근, 권한 범위 오류, 상태 전환 누락

GA4/Amplitude 운영, 실제 사용자 인터뷰, UAT 실시 결과를 보유한 것으로 주장하지 않습니다. 분석 이벤트에는 의료정보·개인정보를 넣지 않습니다.

08 / DECISION MEMO

출시보다 조건부 검증

지금 가능한 결정은 사업화 승인이 아니라 핵심 불확실성을 좁히는 제한적 검증입니다.

RECOMMENDATION

자녀 대리 예약형 병원동행은
검증 후 사업화 여부를 결정합니다.

선택 가능한 방식

제한 지역 직접 제공 또는 기존 사업자 협업·중개. 수익 인식, 공급 원가, 책임 범위를 비교합니다.

결정 전 확보 자료

고객 인터뷰, 매니저 공급 단가, 실제 이용 흐름, 개인정보·안전 검토, 계약 조건.

G0~G2 검증 기준을 충족하지 않으면 확대하지 않습니다.

IT기획 · 전략기획 · PM 채용 요구 역량과의 연결

요구 역량이 사례에서 제시한 근거증빙 수준
시장·문제 정의경쟁 앱·리뷰 조사, 예약자·이용자 역할 분리팀 조사 범위 확인 · 원자료 재검증 필요
IA·PRD·정책사용자 여정, 기능·권한·예외와 인수 기준 정리프로토타입 구현 + 후속 기획안
BM·재무거래액·수수료 매출·공헌이익 모델과 민감도가정 기반 · 실측 손익 미확보
PM·품질·데이터우선순위, 게이트, QA 과업, 퍼널·KPI 정의원본 자동 테스트 일부 확인 · 일정/실사용 지표는 제안
