01 · 문제, 목표와 범위

문제: 예약을 결정하는 자녀와 서비스를 이용하는 부모의 역할이 다릅니다. 비교·동의·예약·공유·복구 과정에서 권한 혼동이 생길 수 있습니다.

제품 목표: 예약자·이용자 정보 구분, 예약 소유권 보호, 기간 제한 공유, 상태 충돌 방지, 운영 조회의 경계를 명확히 합니다.

구분포함제외·후속 검증
현재 제품 범위예약 소유권·공유 토큰·상태 전이·화면 시연실제 의료기관 예약·결제·매니저 자동 배정
권한 원칙소유자 인증·복구 키·공유 토큰을 구별하고 만료·폐기를 처리가족·의료정보에 대한 실운영 동의 프로세스 승인
운영 검증기능 테스트 코드와 시연 화면을 기준으로 QA 조건 정의실서비스 장애 대응·실사용자 UAT·제휴 계약 승인

핵심 사용자 과업: 가족 정보 확인 → 병원·매니저 비교 → 동의·신청 → 예약·진행 확인 → 공유·복구 → 재예약. 프로토타입 구현과 실제 서비스 제공을 구분합니다.

02 · 요구사항 R-01~R-06와 수용 기준

요구사항행동·정책·예외수용 기준구현·검증 상태
R-01
예약자·이용자 역할 분리		자녀(예약자)와 부모(이용자) 정보·동의 범위를 구분한다. 의료정보는 동의 전에 매니저에게 제공하지 않는다.두 역할과 동의 안내를 구별할 수 있고, 동의 누락 시 신청 제한 정책이 명시돼 있다.정책·개념 시안만 확인 / 실제 동의·개인정보 운영 QA 미실시
R-02
예약 소유권		계정이 소유한 예약만 조회·변경할 수 있다. 계정 로그인과 예약 복구 키 접근 경계를 구분한다.본인 예약은 조회·복구할 수 있고, 비소유 계정 접근은 거부되어 기존 상태가 유지된다.계정 소유권 테스트 코드 / 자동 실행 기록은 별도 확인
R-03
공유 발급·권한·만료·폐기		소유자의 복구 키로 공유 링크를 발급·교체·폐기한다. 현재 기본 정책은 공유자 변경 허용이며, 읽기 전용 정책은 별도 설정이다. 만료·폐기·교체 토큰은 차단한다.유효 토큰으로 조회 가능; 새 발급 시 구 토큰 차단; 만료·폐기 토큰 접근·변경 차단; 읽기 전용 PATCH 403 및 예약 revision 유지.공유·권한 테스트 코드 / 자동 실행 기록은 별도 확인
R-04
예약 상태·버전 충돌		요청→확정→동행→완료 등 허용된 상태 전이만 적용한다. PATCH 시 기대 revision이 다르면 409 충돌로 거절한다.유효 전이만 처리; 잘못된 전이·오래된 변경은 차단; 기존 예약 기록을 유지하고 재조회하도록 안내한다.상태 전이 테스트 코드 · 충돌 처리 구현 / 충돌 UI 통합 QA 미실시
R-05
매니저 비교·선택		지역·가능 시간·역할 정보를 비교하되 시안 정보와 실제 배정 확정을 구별한다.비교 기준과 미확정 상태를 화면에 표시하고, 실제 공급 확인·배정이 구현된 것으로 오해시키지 않는다.개념 시안 / 실제 공급·배정 연동 미구현, 사용자 QA 미실시
R-06
진행·운영 조회		예약 진행·공유 이력을 확인하고 운영 샘플을 읽기 전용으로 제공한다.조회·필터·상세 화면에서 실제 운영 배정·의료정보 조회를 제공한다고 주장하지 않는다.운영 시연 화면 / 현장 운영·담당자 UAT 미실시

수용 기준은 검수 조건입니다. 모든 항목이 통과됐다는 뜻이 아닙니다. 기본 공유 링크의 쓰기 권한은 현재 구현 기준이며, 읽기 전용은 별도 정책으로 적용됩니다.

05 · 사용자 UAT 시나리오 (실시 전)

과업사용자 행동통과 조건기록 상태
UAT-01 가족 대리 예약자녀가 부모 정보·동의 범위를 구분하여 신청필수 정보·동의 조건 이해, 오류 시 수정 경로 확인미실시
UAT-02 매니저 비교지역·가능 시간·역할 비교, 시안/확정 정보 판단선택 근거 설명, 배정 확정으로 오인하지 않음미실시
UAT-03 공유 권한보호자가 링크를 발급·폐기하고 공유자가 조회권한·만료·변경 가능 여부를 정확히 이해미실시
UAT-04 충돌·복구오래된 화면에서 변경 후 다시 진입오류 원인·서버 최신 상태·재시도 경로 이해미실시
UAT-05 운영 대응변경·취소·연락 실패 사례에 대한 담당 절차 확인원인·책임 주체·고객 안내·종료 기준 합의미실시
