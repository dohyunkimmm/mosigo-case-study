01 · PROJECT OVERVIEW

프로젝트 개요

MOSIGO는 병원동행이 필요한 부모와 직접 동행하기 어려운 자녀 사이의 정보 확인·서비스 신청·진행 공유 과정을 하나의 흐름으로 묶는 서비스 기획안입니다.

해결할 문제

자녀는 부모의 진료를 대신 준비해야 하지만, 서비스 조건과 이용자 동의, 진행 상황을 각각 확인해야 합니다.

제품 기회

검색·비교·부모 동의·신청·진행 공유를 한 흐름으로 연결합니다.

시장·비용 분석은 사업기획서에서, 사용자 경험과 기능은 이 문서에서 다룹니다.

02 · OBJECTIVE

제품 목표

누구에게 어떤 가치를 제공하며, 무엇을 먼저 검증할지 정합니다.

핵심 목표

“자녀가 부모의 병원동행을 안심하고 준비하고, 신청 이후의 진행 상태를 쉽게 확인할 수 있는 경험을 제공한다.”

  1. 비교 부담 완화: 서비스 범위·지역·시간·매니저 정보를 같은 기준으로 보여줍니다.
  2. 대리 신청 명확화: 신청자(자녀)와 이용자(부모)의 역할 및 동의 항목을 구별합니다.
  3. 진행 확인 개선: 예약 상태와 공유 권한, 변경 사항을 한눈에 이해할 수 있도록 설계합니다.

우선순위는 제품기획 가설이며, 실제 고객 선호에 따라 조정합니다.

03 · USER PERSONAS

사용자 페르소나

사용자 조사에서 검증할 핵심 페르소나 가설입니다.

핵심 사용자 · 예약자

부모의 진료를 준비하는 자녀

상황: 근무나 거주지 문제로 부모와 매번 동행하기 어렵습니다.

필요: 믿을 만한 조건 비교, 대리 신청, 일정·진행 확인, 변경 안내

주요 과업: 탐색 → 비교 → 동의 요청 → 신청 → 진행 확인

서비스 이용자

병원동행 서비스를 이용하는 부모

상황: 방문 일정과 현장 동행 정보를 이해하고 서비스 이용을 결정해야 합니다.

필요: 이해하기 쉬운 안내, 동의·거부 선택, 이동·현장 안전 정보

주요 과업: 내용 확인 → 동의 → 동행 이용 → 이상 시 연락

05 · KEY FEATURES / REQUIREMENTS

핵심 기능·요구사항

사용자가 할 일, 화면에서 제공할 정보, 예외 처리 원칙을 기준으로 정리했습니다.

ID기능사용자 관점 요구사항중요한 화면·정책우선순위
R-01예약자·이용자 구분자녀가 부모를 대신 신청할 때 두 사람의 정보를 혼동하지 않아야 합니다.예약자/이용자 입력 구분, 이용자 동의 안내, 동의 누락 시 진행 제한우선
R-02내 예약 확인·복구신청자는 본인 예약을 다시 찾고 현재 상태를 확인할 수 있어야 합니다.내 예약 목록·상세, 본인 확인, 다른 계정 정보 접근 제한우선
R-03진행 상황 공유자녀가 필요한 사람에게 진행 정보를 공유하고 공유 범위를 관리할 수 있어야 합니다.공유 대상·변경 가능 범위 안내, 링크 만료·철회, 접근 실패 시 안내우선
R-04예약 상태·변경 안내신청 이후의 진행 단계와 취소·변경 결과를 이해할 수 있어야 합니다.요청/확정/동행/완료 등 상태 표시, 오래된 정보 수정 시 재확인 안내우선
R-05매니저 정보 비교이용 조건을 비교하고 본인 상황에 맞는 선택을 할 수 있어야 합니다.지역·가능 시간·동행 범위 비교, 배정 확정 상태 구분핵심 경험·운영 검증 필요
R-06진행·운영 정보 조회문의나 변경 요청이 있을 때 필요한 정보를 확인할 수 있어야 합니다.진행 이력·상세 조회, 개인정보 접근 범위, 운영 책임 안내후속 운영 검증
요구사항 해석 · ID는 기능을 추적하기 위한 번호입니다. 예컨대 R-03의 핵심은 서버 요청 방식이 아니라, 사용자가 무엇을 공유할 수 있고 언제 접근이 끝나는지 이해하는 것입니다.

사용자 스토리

사용자원하는 행동기대 가치연결 기능
자녀병원동행 조건과 매니저 정보를 비교하고 싶다.부모에게 맞는 서비스를 선택하기 위해R-05
자녀부모 정보를 구분해 대신 신청하고 싶다.부모의 동의와 신청 내역을 명확히 하기 위해R-01·02

부모내가 이용할 서비스와 동의 항목을 이해하고 싶다.안심하고 이용 여부를 결정하기 위해R-01

위 문장은 실제 인터뷰 인용이 아니라 요구사항을 정리하기 위한 사용자 스토리입니다.

09 · TECHNICAL REQUIREMENTS

기술 요구사항

기술 구현 방법보다 서비스에서 지켜야 할 기준을 명시합니다.

  • 개인정보: 예약자·이용자 정보를 구별하고 필요한 정보만 요청합니다. 이용자 동의와 정보 접근 범위는 운영 전 검토가 필요합니다.
  • 권한: 예약 소유자·공유받은 사람·운영자의 확인 범위를 구분하고 권한이 없으면 정보 노출을 제한합니다.
  • 상태 정합성: 변경이나 취소 요청이 겹칠 때 최신 상태를 다시 확인하도록 안내합니다.
  • 이용성: 모바일에서 읽기 쉬운 정보 구조, 분명한 버튼·오류 문구, 이전 단계 복귀를 제공합니다.
  • 운영 로그: 변경·취소·공유 이력의 기록 범위와 보존 정책은 실제 운영 계약 단계에서 확정합니다.
