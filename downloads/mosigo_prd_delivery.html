MOSIGO · SERVICE PM · PRODUCT REQUIREMENTS

요구사항 정의서(PRD)와 프로젝트 인수·검수 기준

자녀가 부모의 병원동행 서비스를 탐색·신청·공유하는 흐름을 요구사항, 예외 처리, 테스트, 운영 인수 기준으로 연결한 현행 산출물입니다.

문서 기준: 2026-11-08범위: 기존 MOSIGO 프로토타입구현·검수·후속 계획 분리
적용 경계 · MOSIGO는 병원 실제 예약·실결제·의료 판단·운영자 자동 배정을 제공하지 않습니다. 아래 인수 기준 중 실제 서비스 운영이 필요한 항목은 제안 기준으로 표시합니다. 고객 협의 완료나 실운영 승인으로 해석하지 않습니다.

01 · 문제와 목표

문제: 서비스 신청을 결정하는 자녀와 서비스를 이용하는 부모의 역할이 다르고, 매니저 비교·동의·진행 공유·예약 복구가 분절될 수 있습니다.

목표: 예약자/이용자 정보를 구분하고, 매니저 비교 → 동의·신청 → 상태 확인 → 공유·복구 흐름의 필수 조건과 예외를 명확히 합니다.

우선 범위: 계정 소유 예약, 공유 권한·만료·폐기, 예약 상태 충돌 처리, 읽기 전용 운영 시연. 실제 의료기관·매니저·결제 제휴는 제외합니다.

02 · 요구사항·인수 기준·검증 연결

요구사항 ID정의 및 예외인수 기준근거·상태
R-01
역할 분리		예약자와 동행 대상자를 별도 필드로 구분; 대상자 동의 없이 실제 민감 정보를 제공하지 않도록 설계화면에서 두 주체의 정보를 구별하고, 동의 관련 선택을 명확히 안내화면·서비스 정책 설계 / 실제 의료 동의 검증은 후속
R-02
예약 소유권		계정이 소유한 예약만 서버에서 조회·변경; 다른 계정 접근 제한비소유 계정의 조회·변경 요청 거절, 본인 예약 상태 유지소유권 테스트 / 구현·테스트
R-03
공유·권한		공유 발급·만료·폐기; 기본 편집 권한과 별도 읽기 전용 설정을 구분만료·폐기 링크 차단, 읽기 전용은 조회 외 변경을 허용하지 않음공유 테스트 / 구현·테스트
R-04
상태·충돌		중복 예약 변경과 오래된 revision/ETag 갱신을 거부하고 현재 상태 복구를 안내최신 서버 상태 확인, 중복·충돌 시 기존 기록 무결성 유지상태 테스트 / 구현·테스트
R-05
매니저 비교		가능 시간·역할·조건을 확인하고, 확정되지 않은 매니저 배정은 시연 정보로 표시사용자가 비교 근거를 확인할 수 있고 실제 배정 확정으로 오인하지 않음프로토타입·화면 QA / 실제 배정은 미구현
R-06
진행·운영		예약 상태·복구·공유 이력 확인; 운영 샘플은 읽기 전용샘플 화면에서 변경 API 없이 현황 조회·필터·상세 탐색운영 샘플 / 시연·테스트

위 근거는 기능 구현 또는 계약 테스트의 범위입니다. 의료기관 예약·결제·현장 매니저 배정과 실제 사용자 인수 서명을 의미하지 않습니다.

03 · 우선순위·변경관리·산출물

단계범위관리 산출물검수·진입 조건
P0 · 기준선역할·권한·예약 상태·개인정보 처리의 핵심 요구사항요구사항 목록, 상태 전이, 예외 및 담당 기준필수 정책 충돌·누락이 없도록 요구사항 검토
P1 · 구현 검수예약 변경·공유·복구·충돌 처리와 화면 연결요구사항-테스트 추적표, 오류 재현 기록, 수정 이력자동 검증 통과 및 검수 미해결 항목 분류
P2 · 인수 준비운영 샘플, 사용자 안내, 권한·만료·문제 복구 절차인수 체크리스트, 교육 안내, 제한사항·후속 계획실제 운영/제휴 미구현 사항은 승인 범위에서 제외

변경 요청 처리 원칙

  1. 변경 요구를 ID, 사유, 영향을 받는 화면·API·권한·일정으로 기록합니다.
  2. 기존 인수 기준과 충돌하는지 확인하고 P0/P1/P2 우선순위를 재판정합니다.
  3. 변경 적용 후 해당 요구사항과 연결된 테스트를 실행하고 미검증 부분을 표시합니다.
  4. 산출물·사용자 안내·인수 체크리스트를 같은 버전으로 갱신합니다.

단계는 실무 적용을 위한 수행 관리 기준입니다. 과거 실제 발주 일정·고객 승인 일자를 임의로 설정하지 않았습니다.

04 · UAT 및 인수인계

UAT·검수

  • 정상 신청·재접속·복구 흐름
  • 권한 없는 예약 접근 차단
  • 공유 만료·폐기·읽기 전용 처리
  • 오래된 버전·중복 변경 충돌 안내
  • 모바일·키보드·가독성 확인

기술 테스트 결과와 실제 사용자 UAT 승인 여부를 별도 기록합니다.

운영·교육 인수 패키지

  • 화면별 주요 사용 방법과 제한사항
  • 권한·동의·공유 링크 발급·폐기 기준
  • 예약 복구 실패 시 확인 순서
  • 고객 문의 접수 → 원인 분류 → 재검수 기록
  • 잔여 이슈·정책 미확정 항목 목록

실서비스 운영 교육과 고객 인수는 별도 진행 조건입니다.

05 · 검토 완료 기준

기능별로 요구사항 ID → 구현 경계 → 테스트 근거 → 미검증 항목 → 인수 판단을 한 행으로 연결합니다. 기술 검증 통과와 실제 운영·고객 인수를 동일하게 표현하지 않습니다.
